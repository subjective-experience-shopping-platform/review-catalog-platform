# semantic-review-extraction-experiment

리뷰에서 어떻게 속성을 추출할 것인지 선행 연구를 조사하고 실험을 설계, 검증하여 최적의 방법을 도출하는 프로젝트입니다.

본 레포지토리에서는 리뷰에서 속성을 어떻게 추출할지 선행 연구를 토대로 2x2 실험을 진행합니다. 실험을 통해 aspect과 status, sentiment를 갖춘 Opinion Units이라는 속성 추출 단위를 계층적으로 군집화하였을 때 리뷰의 정보를 가장 잘 반영한다는 결론을 도출하였습니다.

README는 전체 실험 과정을 대략적으로 설명하며 목차는 다음과 같습니다.

1. 문제 제기
2. 선행 연구 조사
3. 실험 설계
4. 실험 결과 및 의의
5. 한계점 및 후속 연구 설계
6. 프로젝트 구성 및 재현 방법.

## 1. 문제 제기

크기, 성능, 무게와 같은 객관 속성은 사용감을 대변할 수 없기에 사람들은 상품의 별점과 리뷰와 같은 체감 속성 정보를 추가로 확인하여 상품 구매를 고려합니다. 하지만 별점 시스템은 형식이 정형화되면서 [신뢰성이 떨어져가기](https://techblog.woowahan.com/25888/)에 리뷰의 중요성이 대두되고 있습니다. 기존 카탈로그 시스템은 리뷰와 같은 비정형 데이터를 처리하기에 적합하지 않아 활용이 제한됩니다.

이를 해결하기 위해 다양한 선행 연구에서는 LLM을 활용해 리뷰에서 속성을 직접 추출하여 반정형 데이터 카탈로그를 구축하는 방법을 제안해왔습니다. 그러나 추출의 자유도를 높이면 유사한 의미의 표현이 파편화되어 상품 간 비교와 집계가 어려워지고 반대로 가능한 속성이나 규칙을 미리 제한하면 새로운 상품과 표현을 충분히 포괄하기 어렵다는 trade-off가 존재합니다.

본 프로젝트는 이 trade-off를 완화하기 위해 문제를 다음 두 질문으로 구체화했습니다.

1. 리뷰의 속성과 근거를 충분히 보존하면서 구조화할 수 있는가?
2. 추출된 다양한 표현의 의미를 유지하면서도 비교·집계 가능한 수준으로 통제할 수 있는가?

첫 번째 질문에서는 ABSA와 Opinion Units를 비롯한 선행 연구를 바탕으로 근거를 포함한 구조화된 속성 추출 방식을 검토하고 두 번째 질문에서는 의미적으로 유사한 표현을 통합하는 속성 정규화 방식을 검토합니다.

## 2. 선행 연구 조사

### Opinion Units

[Opinion Units](https://aclanthology.org/2025.nodalida-1.24.pdf)는 LLM을 통해 단순히 Aspect와 Sentiment만 추출할 경우 Sentiment 판단에 직접적인 영향을 미친 원문의 구문을 확인하기 어려워 후속 분석이 제한될 뿐만 아니라 LLM의 Sentiment 예측 정확도 또한 낮아질 수 있다고 지적합니다.

이에 따라 최소 속성 추출 단위인 Opinion Unit을 제안합니다. Aspect와 Sentiment에 excerpt 속성을 추가해 해당 판단이 원문의 어떤 구문에 근거하는지 명시합니다. 프롬프트에는 원자성, 단사성, 완전성, 맥락성이라는 네 가지 원칙 준수를 명시합니다.

본 실험에서는 Opinion Units의 네 가지 원칙과 세 가지 속성을 기반으로 status와 opinion을 추가하여 총 다섯 가지 속성을 기본 추출 단위로 설정하였습니다. 이를 선행 연구와 동일하게 Opinion Unit이라고 부르며 LLM 기반 속성 추출의 최소 단위로 사용합니다.

- **raw_aspect**: 평가하거나 관찰한 제품의 구체적인 속성, 구성 요소, 경험 결과를 나타내는 명칭.
- **raw_status**: 해당 `raw_aspect`의 상태, 경험, 조건, 현상 또는 값을 나타내는 명칭.
- **excerpt**: 의견 단위의 근거가 되는 리뷰 원문의 정확하고 연속된 문자열.
- **opinion**: 관련 맥락·비교·정도·결과·불확실성을 보존하여 관찰이나 평가를 간결하게 정리한 문장.
- **sentiment**: 해당 속성과 상태에 대한 감정을 `positive`, `negative`, `mixed`, `neutral`, `unknown` 중 하나로 표현한 값.

선행 연구의 aspect는 ‘가격이 비쌈’, ‘파손이 있음’과 같이 속성과 상태가 결합된 형태이기 때문에 고유한 속성값이 지나치게 많이 생성되어 군집 형성과 공통 속성 분석이 어려웠습니다. 이에 본 실험에서는 속성과 상태를 각각 aspect와 status로 분리하여 다루어 공통 속성 분석의 유효성을 높이고자 하였습니다.

### 계층적 속성 군집화

[Distantly Supervised Aspect Clustering and Naming for E-Commerce Reviews](https://aclanthology.org/2022.naacl-industry.12.pdf)는 초기 군집이 군집명 생성 모델의 학습 데이터를 만들고 군집명 생성 모델이 다시 군집 모델의 학습 데이터를 만드는 상호 개선 구조의 프레임워크를 제안합니다. 전체 과정은 세 단계로 진행됩니다.

1. 리뷰 임베딩 벡터를 Input으로, TF-IDF와 군집 내 코사인 거리를 통해 선정된 군집 대표 속성을 정답 Label으로 하여 T5 모델을 fine-tuning합니다.
2. 텍스트 임베딩 모델을 리뷰 corpus에 대해 MLM 목적함수로 추가 사전학습합니다. 이후 fine-tuning된 T5가 생성한 군집명과 군집 medoid 간의 유사도를 기반으로 triplet 데이터를 구성하고 triplet loss를 적용하여 임베딩 모델을 fine-tuning합니다.
3. Fine-tuning된 텍스트 임베딩 모델로 리뷰를 임베딩하고 계층적 군집화를 수행합니다. 이후 최종적으로 fine-tuning된 T5 모델을 통해 군집 속성명인 Aspect을 추출합니다.

본 실험에서는 선행 연구의 리뷰 임베딩과 계층적 군집화 방법을 가져와 적용합니다. 다만 본 실험은 LLM을 통해 리뷰에서 속성을 직접 추출하므로 군집화의 주된 목적은 '대표 속성 후보 추출'이 아니라 의미적으로 유사하지만 표현이 서로 다른 속성을 통합하는 '의미 기반 속성 정규화'입니다.

## 3. 실험 설계

### 2x2 실험 설계

선행 연구를 근거로 다음 두 가지 실험 기준과 가설을 설정합니다.

1. **기준 1: 구조화 여부.**
	- **가설**: Opinion Units 기반의 구조화된 속성 추출은 단순 attribute-sentiment 추출보다 리뷰의 주요 속성과 맥락을 더 포괄적으로 보존하고 추출 결과의 근거 추적성과 후속 분석 가능성을 높일 것이다.
2. **기준 2: 정규화 여부.**
	- **가설**: 계층적 군집화를 통한 속성 정규화는 개별 속성의 의미적 정보를 유지하면서 의미적으로 유사한 표현을 통합하여 속성의 일관성과 집계·비교 가능성을 높일 것이다.
	- 정규화 이전의 속성에는 `raw_*` 접두사를 사용하여 정규화된 속성과 구분합니다. 정규화를 수행하지 않는 실험에서는 정규화 전후의 속성값을 동일하게 설정합니다.
	- 실험 B와 달리 실험 D는 Opinion Units을 사용하므로 정규화 대상이 aspect와 status 두 가지입니다. 이에 따라 실험 B에서는 raw_attribute를 기준으로 한 번만 군집화를 수행하지만, 실험 D에서는 먼저 raw_aspect를 군집화한 뒤 동일한 aspect를 가진 군집 멤버를 대상으로 raw_status를 다시 군집화합니다. 즉, 실험 D에서는 총 두 단계의 정규화를 수행합니다.
	- 군집화는 텍스트 임베딩 벡터를 L2 정규화한 뒤 cosine distance를 기준으로 고정 임계값에서 절단하는 complete-linkage 계층적 응집 군집화(Hierarchical Agglomerative Clustering)**를 사용합니다.
	- singleton 군집인 경우, 정규화 전 값인 `raw_*` 를 정규화된 속성값으로 그대로 설정합니다.
	- 텍스트 임베딩은 Huggingface의 `snunlp/KR-SBERT-Medium-extended-klueNLItriplet_PARpair_QApair-klueSTS` 모델을 사용하였습니다.

두 실험 기준의 효과를 비교하기 위해 Opinion Units를 활용한 구조화된 속성 추출과 계층적 군집화를 활용한 속성 정규화를 각각 독립변수로 설정하고 2×2 형태의 4가지 실험을 수행합니다. 실험에 사용되는 데이터는 AI Hub의 [속성 기반 감정 분석 데이터](https://aihub.or.kr/aihubdata/data/view.do?currMenu=115&topMenu=100&aihubDataSe=data&dataSetSn=71603)에서 추출한 TV·모니터 제품 9종의 리뷰 1,608개로 구성됩니다.

- **실험 A(비구조화 + 미정규화)**: 각 리뷰에서 단순히 속성과 sentiment만을 추출하며 정규화는 수행하지 않습니다.
- **실험 B(비구조화 + 정규화)**: 각 리뷰에서 단순히 속성과 sentiment만을 추출한 뒤 군집화를 통해 속성을 정규화합니다.
- **실험 C(구조화 + 미정규화)**: 각 리뷰에서 Opinion Units 형식으로 속성을 추출하며 정규화는 수행하지 않습니다.
- **실험 D(구조화 + 정규화)**: 각 리뷰에서 Opinion Units 형식으로 속성을 추출한 뒤 군집화를 통해 속성을 정규화합니다. 이때 aspect과 status 속성에 따라 hard boundary를 적용하여 군집화합니다.

비교 대상인 두 가지 실험 조건을 제외하고 모델, 데이터셋 및 군집화 조건 등 나머지 조건은 가능한 한 동일하게 설정합니다. 다만 LLM의 생성 결과를 완전히 결정적으로 통제하는 것은 아니므로 동일한 조건에서 실험을 반복하더라도 결과의 완전한 재현성은 보장하기 어렵습니다.

### 평가 설계

본 실험은 정량 평가와 정성 평가로 구분됩니다. 실험 설계는 [Distantly Supervised Aspect Clustering and Naming for E-Commerce Reviews](https://aclanthology.org/2022.naacl-industry.12.pdf)의 평가 방법을 기반으로 구성하였습니다.

#### 정량적 평가

출력 결과를 정량적으로 측정하여 각 실험이 사전에 정의한 정책을 준수하였는지, 생성된 결과가 분석에 충분히 유효한지를 평가합니다.

1. **데이터 무결성 검사**
	- 원본 입력 데이터의 행 유실 여부, 허용되지 않은 sentiment 값의 존재 여부, 군집화 알고리즘의 최대 거리 임계값 준수 여부 등을 검사합니다.
	- 데이터 무결성 검사 항목은 이후 비즈니스 로직을 위한 데이터 파이프라인을 설계할 때 품질 검증 규칙으로 활용합니다.
2. **정규화 유효성 평가**
	- 고유 속성 감소율과 singleton 군집 비율 등을 측정하여 속성 정규화가 어느 정도 유효한지 평가합니다.
3. **군집 품질 평가**
	- 정규화를 수행하는 실험 B와 D를 대상으로 실루엣 점수를 측정합니다.
	- 또한 인접한 군집 쌍을 추출하여 위험 군집 분석을 수행하고 의미적으로 서로 다른 속성이 하나의 군집으로 병합되는 오병합 사례를 확인합니다.
	- 이러한 결과는 계층적 군집화의 거리 임계값과 군집화 수준을 조정하는 데 활용합니다.

정량 평가, 특히 두 번째와 세 번째 평가는 보조 지표로 해석합니다. 고유 속성 수의 감소나 군집 분리도가 개별 속성의 의미적 품질을 직접 보장하지는 않기 때문입니다. 정량 평가 결과는 다음의 정성 평가와 함께 종합적으로 사용합니다.

##### 리뷰 수준 평가

전체 데이터셋 중 무작위로 100개의 샘플을 추출(재현 가능)합니다. 이후 각 리뷰에 대한 실험 결과를 무작위 순서로 제시하며 서로 다른 3명의 평가자가 다음 4가지 척도를 기준으로 평가합니다.

- **사실 충실성**: 원문 리뷰에 존재하지 않는 내용을 생성하거나 허위 사실을 포함하지 않았는가?
- **핵심 설명력**: 리뷰 작성자의 핵심 의도와 주요 불만·만족 요인을 정확하게 대변하는가?
- **정보 포괄성**: 리뷰에 포함된 중요한 속성이나 세부 사항을 빠뜨리지 않고 충분히 추출하였는가?
- **결과 선호도**: 실험 A,B,C,D의 결과 중 평가자가 최종 결과로 가장 선호하는 형태는 무엇인가?

사실 충실성, 핵심 설명력, 정보 포괄성은 각각 1점에서 5점까지의 리커트 척도로 평가합니다. 결과 선호도는 네 가지 실험 결과 중 하나를 선택하는 방식으로 비교 우위를 평가합니다.

##### 군집 수준 평가

실험 B,D의 singleton이 아닌 군집 중에서 서로 다른 100개의 군집을 선정(재현 가능)합니다. 각 군집의 정규화 전 멤버와 정규화된 대표명을 다음 두 가지 척도로 평가합니다.

- **응집성**: 동일한 군집으로 묶인 `raw_*` 속성들이 실제로 같거나 충분히 유사한 의미를 나타내는가?

## 한계점 및 후속 연구

본 실험에서는 일부 내용을 의도적으로 생략하거나 단순화하였습니다. 이는 완전한 실험을 설계하고 분석하는 것보다, 가설을 기반으로 실험을 설계·수행한 뒤 검증된 결과를 지속 가능한 비즈니스 로직으로 연결하는 사이클을 빠르게 수행하는 것이 실험의 시작점으로서 더 중요하다고 보았기 때문입니다.

본 실험에서 대표적으로 생략하거나 단순화한 내용은 다음과 같습니다.

- **매개변수 설정 근거 부족**: AI·ML 실험에서는 하이퍼파라미터를 비롯한 주요 매개변수에 따른 실험과 튜닝은 필수적입니다. 그러나 본 실험에서는 제한된 시간 안에 전체 제품 엔지니어링 사이클을 수행하는 데 집중하기 위해 실험자의 직관을 바탕으로 일부 매개변수를 탐색하고 설정하였습니다.
- **별도의 감성 분석 모델 미적용**: 다수의 선행 연구와 사례에서는 sentiment를 추출할 때 LLM 대신 BERT 계열의 감성 분석 모델이나 미세 조정된 T5 모델을 사용합니다. 이러한 방식은 일반적으로 추론 비용과 처리 속도 측면에서 유리하며 충분한 학습 데이터가 확보된 경우 정확도 측면에서도 더 나은 결과를 보일 수 있습니다.
	- 본 프로젝트에서는 구조화된 속성 추출과 정규화 실험에 집중하고 파이프라인의 다른 요소를 단순하게 유지하기 위해 별도의 감성 분석 모델 대신 LLM을 사용하였습니다.
	- 후속 연구에서는 LLM이 추출한 opinion 또는 aspect-status 쌍을 입력으로 사용하는 별도의 감성 분석 모델을 적용하고, 비용·속도·정확도를 비교할 필요가 있습니다.
	- [Sentiment Analysis in the Era of Large Language Models: A Reality Check](https://aclanthology.org/2024.findings-naacl.246.pdf)

실험 설계 단계에서 여러 선행 연구를 조사하였으나 시간과 구현 범위를 고려하여 실제 실험에는 적용하지 않은 방법도 존재합니다. 이를 바탕으로 후속 연구를 제안할 수 있습니다.

- **임베딩 모델 fine-tuning**: 리뷰 텍스트로 fine-tuning한 임베딩 모델을 통해 군집화를 수행하면 더욱 분리된 표현력을 얻을 수 있을 것으로 기대합니다.
	- [Distantly Supervised Aspect Clustering and Naming for E-Commerce Reviews](https://aclanthology.org/2022.naacl-industry.12.pdf)에서 단순한 텍스트 임베딩은 리뷰 표현을 충분히 반영하지 못하기에 SBERT-STS와 같은 텍스트 임베딩 모델을 리뷰 텍스트로 MLM(Masked Language Model) 학습한 뒤 Siamese 방식의 triplet loss로 fine-tuning하는 것을 제안합니다.
	- 후속 연구에서는 이러한 도메인 적응이 실루엣 점수, singleton 비율, 속성 압축률 및 사용자 평가에 미치는 영향을 비교할 수 있습니다.
- **카테고리별 편향 조정**: [우아한 형제들의 이승원 DS님의 사례](https://techblog.woowahan.com/25888/#toc-4)에서는 상품 카테고리에 따라 리뷰의 분포와 표현 방식에 편향이 존재할 수 있음을 설명합니다.
	- 본 프로젝트에서는 TV·모니터라는 제한된 범주의 상품만을 다루었으므로 카테고리 간 차이를 별도로 고려하지 않았으나 다양한 카테고리를 다루는 실제 로직 및 후속 연구에서는 카테고리별 편향을 고려해야 합니다.
- **aspect와 status의 정규화 전략 분리**: 본 실험은 raw_aspect를 먼저 군집화한 뒤 동일한 aspect 군집에 속한 raw_status를 다시 군집화하는 2단계 정규화를 적용하였습니다. 그러나 실험 D에서 aspect는 53.10%의 압축률을 기록한 반면 status의 압축률은 9.40%에 그쳤습니다. 이 결과에 따르면 의미적 유사도를 중심으로 설계한 현재의 군집화 방식은 aspect 통합에는 유효했지만 status 정규화에는 제한적으로 작동했습니다.
	- 후속 연구에서는 status를 일반적인 텍스트 군집화 대상으로 처리하기보다, 방향성·강도·비교·수치·조건을 구조화한 뒤 규칙 또는 별도의 모델을 통해 정규화하는 방식을 검토할 수 있습니다.

## 실험 재현 및 파일 구조 설명

### 실험 재현

`uv sync`를 통해 가상환경을 활성화한 다음 아래 명령어를 순차적으로 입력하면 본 실험을 재현할 수 있습니다. 다만 LLM 특성상 완벽한 재현성은 보장되지 않습니다.

1. `build_units_dataset.py`: `data/origin_source`의 데이터셋에서 모니터에 해당하는 9개의 상품을 추출해 `data/dataset.parquet`를 생성하고, 추출된 리뷰에서 속성을 추출해 `data/attribute_units.parquet`와 `data/opinion_units.parquet` 파일을 생성합니다.
2. `run_experiment.py`: 2x2 실험을 진행합니다. 군집화, 정적 보고서와 같은 실험 결과는 `experiment/{date}`에 저장됩니다.
3. `run_user_evaluation.py`: 사용자 평가를 수행하는 Streamlit 서버를 실행합니다. 사용자 평가가 3회 이상 존재할 경우에만 `experiment/{date}/report.md` 경로에 사용자 평가까지 반영된 최종 보고서가 생성됩니다.

huggingface에서 모델을 가져와 models 경로에 넣어야 하며 AI HUB에서 데이터를 가져와 data/origin_source에 넣어야 합니다. (혹은 config.yaml에서 경로를 수정해도 됩니다.)


### 파일 구조 설명

- data: 원본 혹은 실험에 사용될 데이터셋.
  - origin_source: AI HUB에서 다운로드한 원본 데이터셋.
  - dataset.parquet: src/build_dataset.py를 통해 사용자가 직접 선정한 9개의 모니터 제품을 origin_source에서 내용 수정 없이 추출한 데이터셋.
  - attribute_units.parquet: dataset.parquet에서 attribute_units 정책에 따라 추출한 속성을 저장한 데이터셋. 경로는 config.yaml의 extract_attribute.attribute_units로 지정합니다.
  - opinion_units.parquet: dataset.parquet에서 opinion_units 정책에 따라 추출한 속성을 저장한 데이터셋. 경로는 config.yaml의 extract_attribute.opinion_units로 지정합니다.
- prompts: attribute_units과 opinion_units을 추출하는 프롬프트.
- models: 텍스트 임베딩을 수행하는 모델. huggingface에서 직접 가져왔으며 수정하지 않았습니다. 모델은 자동으로 다운로드하지 않습니다.
- experiment: 실험 결과가 YYYY-MM-DD_HHMMSS 형식으로 저장됩니다.
- src
  - build_dataset.py: 사용자가 직접 선정한 9개의 모니터 제품을 origin_source에서 내용 수정 없이 추출한 data/dataset.parquet 파일을 생성합니다.
  - extract_attribute: dataset.parquet 파일에서 두 가지 방법으로 속성을 추출합니다.
  - clustering: 군집화와 관련된 코드들입니다.
  - user_evaluation: 사용자 평가와 관련된 코드들입니다.
  - report: 정적 결과와 사용자 평가를 계산하여 실험별 report.md를 생성하는 코드들입니다.
- build_units_dataset.py: 원본 소스에서 속성 추출을 진행합니다.
- run_experiment.py: 2x2 실험을 진행합니다.
- run_user_evaluation.py: streamlit 서버를 열어 사용자 평가를 진행합니다.
